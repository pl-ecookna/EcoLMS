# Codex Internal Notes

## Текущий статус

- Проект: EcoLMS
- Архитектура: monorepo `pnpm` с `web`, `api`, `worker`, `transcription-service`
- Модуль `meetings` реализован на backend, worker и UI
- STT по умолчанию: `AssemblyAI`, `SaluteSpeech` оставлен как fallback через `MEETING_TRANSCRIPTION_PROVIDER`
- Human auth теперь строится через `EcoAuth/Logto` с web/BFF pattern
- Runtime роли приложения: `admin` и `editor`, источник истины по ролям - `Logto`

## Актуальная архитектура

- `apps/web` - Next.js App Router, UI для LMS и meetings
- `apps/api` - NestJS API, PostgreSQL, Redis, S3 presign
- `apps/worker` - Python worker для обработки курсов и встреч
- `apps/transcription-service` - HTTP-сервис транскрибации

## Deployment notes

- Базовый деплой через Docker Compose / Dokploy
- `web` публикует login/callback/logout/session endpoints и подписывает trusted headers для `api`
- `api` должен принимать пользовательский контекст только от `web`, а не из browser cookies напрямую
- Для uploads используется direct PUT в signed S3 URL
- Для browser-direct uploads обязательно настроить CORS на S3 bucket
- Health-check должен оставаться обязательным для `api`, `postgres`, `redis`, `worker`

## Последние решения

- Для `meetings` upload-flow приведён к прямой загрузке в signed S3 URL, без отдельного proxy-route для `PUT`
- Встречи создаются из UI как одна запись + один файл + автозапуск pipeline
- Стартовое окно приложения унифицировано по стандарту `Monitoring`
- Встроенный user management в `EcoLMS` не добавляется; доступы ведутся только в `EcoAuth`
