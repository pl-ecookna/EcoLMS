# Codex Internal Notes

## Текущий статус

- Проект: EcoLMS
- Архитектура: monorepo `pnpm` с `web`, `api`, `worker`, `transcription-service`
- Модуль `meetings` реализован на backend, worker и UI
- STT по умолчанию: `AssemblyAI`, `SaluteSpeech` оставлен как fallback через `MEETING_TRANSCRIPTION_PROVIDER`
- Human auth теперь строится через `EcoAuth/Logto` с web/BFF pattern
- Runtime роли приложения: `admin` и `editor`, источник истины по ролям - `Logto`

## Актуальная архитектура

- `apps/web` - Next.js App Router, UI для LMS и meetings
- `apps/api` - NestJS API, PostgreSQL, Redis, S3 presign
- `apps/worker` - Python worker для обработки курсов и встреч
- `apps/transcription-service` - HTTP-сервис транскрибации

## Deployment notes

- Базовый деплой через Docker Compose / Dokploy
- `web` публикует login/callback/logout/session endpoints и подписывает trusted headers для `api`
- `api` должен принимать пользовательский контекст только от `web`, а не из browser cookies напрямую
- Для uploads используется direct PUT в signed S3 URL
- Для browser-direct uploads обязательно настроить CORS на S3 bucket
- Health-check должен оставаться обязательным для `api`, `postgres`, `redis`, `worker`

## Последние решения

- Для `meetings` серверный переход в `uploaded` перенесён с `initUpload` на успешный `completeUpload`, чтобы состояние записи соответствовало фактическому завершению multipart upload.
- Для `meetings` отдельный meeting-aware badge теперь показывает "Загрузка подтверждается" вместо зелёной "Загружена", если multipart upload ещё не подтверждён, чтобы не маскировать оборванную загрузку под нормальное состояние.
- Добавлен build-id endpoint для `web` и клиентский guard против stale browser cache: `/api/version` отдает текущий build id, а root layout показывает ненавязчивое уведомление с предложением обновить страницу, если открытая вкладка отстала от нового деплоя
- Исправлена подпись S3 multipart-запросов для `meetings`: query-signed `POST` к S3-compatible storage теперь используют `UNSIGNED-PAYLOAD` и включают дополнительные заголовки вроде `Content-Type` в canonical AWS SigV4 request; это снимает прод-ошибку `SignatureDoesNotMatch` на шаге `uploads/init`
- Для `meetings` в API добавлены вычисляемые метрики времени обработки: `actualSeconds` считается по `processing_started_at -> processing_finished_at`, а `estimatedSeconds` прогнозируется по завершённым встречам близкого размера с приоритетом того же mime-family; UI показывает ETA в уведомлении при старте и в деталях встречи
- Для `meetings` добавлено восстановление подвисших upload-session: если browser успел положить файл в S3, но `meeting_upload_sessions` / `meeting_source_files` не дошли до `completed`, API на `getMeeting` и `startMeeting` теперь проверяет объект через presigned `HEAD`, завершает upload-state и при отсутствии `meeting_jobs` автоматически ставит `audio_prepared` в очередь
- UI `meetings` больше не трактует статус `uploaded` как уже идущую обработку по умолчанию: для неподтверждённой загрузки показывается отдельное ожидание, чтобы не маскировать проблему под зависший pipeline
- В шапках LMS / meetings / prompt editor теперь используется общий `UserMenu` с аватаром; действия `Промпты` и `Выйти` вынесены в dropdown, чтобы убрать дублирование и не держать их как отдельные текстовые элементы
- Logout entrypoints в `web` переведены с `Link` на обычные `<a href="/api/auth/logout">`, чтобы Next App Router не префетчил side-effect route и не сбрасывал сессию фоновым GET при refresh/load
- Переход из LMS в `/meetings` переведён на full-page navigation без prefetch, чтобы обходить stale client-router cache после auth-изменений; сам SSR route `/meetings` и `/api/meetings` в проде отвечает корректно
- Левая панель LMS курсов переведена на стабильный selectable-pattern без вложенных interactive элементов; активный курс теперь подсвечивается по `selectedId`, а повторный клик по уже выбранному курсу перезапрашивает detail, если правая панель осталась пустой
- Для `meetings` upload-flow приведён к прямой загрузке в signed S3 URL, без отдельного proxy-route для `PUT`
- Встречи создаются из UI как одна запись + один файл + автозапуск pipeline
- Стартовое окно приложения унифицировано по стандарту `Monitoring`
- Встроенный user management в `EcoLMS` не добавляется; доступы ведутся только в `EcoAuth`
- SSR-запросы страниц `meetings` в `apps/web` теперь должны ходить к `api` напрямую через trusted auth headers, а не через повторный self-fetch в публичный `/api/*`

## Известные проблемы

- Локальная проверка полного runtime может зависеть от доступности S3 / Redis / Postgres / STT credentials
- Если `meetings` creation падает после создания draft-записи, cleanup через `DELETE /api/meetings/:id` сейчас молча не сработает для роли `editor`, потому что destructive action ограничен `admin`; в списке могут временно оставаться пустые draft-встречи после upload-ошибки
